# Panel spec

A panel spec is a declarative JSON document describing one panel. It is the
contract between the chat agent, the renderer and the Grafana exporter. Data
is never part of the spec — renderers receive `{ spec, frames, timeRange }`.

```json
{
  "version": 1,
  "id": "4c1a0b2e-…",
  "type": "timeseries",
  "title": "CPU busy per core",
  "description": "",
  "queries": [
    { "refId": "A", "expr": "1 - rate(node_cpu_seconds_total{mode=\"idle\"}[5m])", "legend": "core {{cpu}}", "instant": false }
  ],
  "unit": "percentunit",
  "timeFrom": null,
  "options": { "draw": "line", "stack": false, "fill": 0, "lineWidth": 1, "legend": "bottom", "min": 0, "max": 1 }
}
```

## Fields

| Field | Notes |
| --- | --- |
| `version` | Schema version, currently `1`. Bumping it requires a migration in `backend/app/dashboard/migrations.py`. |
| `id` | UUID. Generated by the server when omitted on create. |
| `type` | A registered panel type. `GET /api/panels/types` lists them with their options schema. |
| `title` | 1–120 characters. |
| `description` | Optional free text; exported to Grafana. |
| `queries[]` | 1–8 PromQL queries. `refId` is a single capital letter (`A`, `B`, …). `instant: true` runs an instant query at the end of the range; otherwise a range query whose step is derived from `PROMETHEUS_MAX_DATA_POINTS`. `legend` uses Grafana templating: `{{label}}`. |
| `unit` | One of: `none`, `short`, `percent` (0–100), `percentunit` (0–1), `bytes` (IEC), `decbytes` (SI), `Bps`, `bps`, `s`, `ms`, `ops`, `reqps`, `rps`, `wps`. These are Grafana unit IDs and export unchanged. |
| `timeFrom` | Optional per-panel relative range override such as `24h`. Maps to Grafana's `timeFrom`. |
| `options` | Type-specific; validated against the panel module's options model. Unknown keys are rejected. |

Validation is strict on purpose: unknown fields anywhere fail with a readable
message so that LLM output is either correct or corrected, never silently
mangled. `POST /api/panels/validate` returns the normalised spec (defaults
filled in) without saving it.

## Time range

The time range belongs to the dashboard, not to panels:

```json
{ "timeRange": { "from": "now-6h", "to": "now" }, "refresh": "30s" }
```

Grafana syntax is accepted: `now`, `now-15m`, `now-7d`, `now/d` (start of
today), `now-1d/d`, ISO-8601 timestamps and epoch milliseconds.

## Data frames

Query results are converted once into Grafana-style data frames, one per
query, matched by `refId`:

```json
{
  "refId": "A",
  "fields": [
    { "name": "time", "type": "time", "values": [1700000000000, 1700000030000] },
    { "name": "core 0", "type": "number", "labels": { "cpu": "0", "mode": "idle" }, "values": [0.12, null] }
  ]
}
```

- Timestamps are epoch milliseconds.
- A range (`matrix`) result becomes one frame with a shared time axis and a
  number field per series; missing samples are `null`, never dropped.
- An instant (`vector`) result becomes a table-shaped frame: one row per
  series, a string field per label key and a `value` field.
- `NaN` and `±Inf` become `null`.

## Panel types

### `timeseries`

| Option | Default | Values |
| --- | --- | --- |
| `draw` | `line` | `line`, `bars`, `points` |
| `stack` | `false` | Stack series |
| `fill` | `0` | Area fill opacity, 0–1 |
| `lineWidth` | `1` | 0–5 |
| `legend` | `bottom` | `bottom`, `right`, `hidden` |
| `min` / `max` | unset | Fixed Y-axis bounds |
